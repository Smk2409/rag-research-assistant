# Cloud-Based AI Research Assistant using Retrieval-Augmented Generation and AWS
### Project Report

---

## Abstract
Students increasingly rely on long PDFs, textbooks and papers, yet general-purpose chatbots cannot reliably answer questions about *their* material and may hallucinate. This project presents a serverless, cloud-native **AI Research Assistant** built on **Amazon Web Services**. Users upload documents (PDF, TXT, Markdown, scanned PDFs); the system indexes them and answers natural-language questions using **Retrieval-Augmented Generation (RAG)**. Retrieval combines **dense embeddings (Amazon Titan V2)** with **BM25 keyword search**, fused by **Reciprocal Rank Fusion** and diversified by **Maximal Marginal Relevance**. Answers are generated by a Claude model on **Amazon Bedrock**, constrained to the retrieved context, and accompanied by page-level citations and a confidence indicator. A **Study Studio** converts documents into summaries, flashcards, quizzes and key-term lists. The system uses S3, Lambda, API Gateway, Cognito, DynamoDB, Textract, CloudFront and CloudWatch, is fully described as infrastructure-as-code, and scales to zero cost when idle.

**Keywords:** RAG, Generative AI, AWS, Bedrock, Hybrid Search, BM25, Serverless, Embeddings, Education Technology.

## 1. Introduction
### 1.1 Background
Large Language Models (LLMs) generate fluent text but have fixed training data and may fabricate facts. RAG grounds generation in external documents retrieved at query time, making answers current, private and verifiable.
### 1.2 Problem Statement
Design and implement a cloud-based application that lets students upload documents, ask questions about them, and receive accurate, document-grounded answers with evidence.
### 1.3 Objectives
1. Secure multi-user document upload and storage on AWS.
2. Automatic text extraction (including OCR), chunking and embedding.
3. High-quality retrieval via hybrid search.
4. Grounded answer generation with citations; refusal when evidence is missing.
5. Conversational follow-ups with memory.
6. Study aids generated from the documents.
7. Scalable, low-cost, observable, secure deployment as code.
### 1.4 Scope
Text-based and scanned documents up to 20 MB each; English language; individual (non-shared) workspaces.

## 4. System Design
### 4.1 Architecture
See `docs/architecture.mmd`. Layers: **Presentation** (static SPA on CloudFront/S3) → **API** (API Gateway + Cognito authoriser) → **Compute** (6 Lambda functions) → **AI** (Bedrock, Textract) → **Data** (S3, DynamoDB).
### 4.2 Component responsibilities
| Component | Responsibility |
|---|---|
| `documents` | Create upload tickets, list, delete, issue download URLs |
| `process_document` | Text extraction, OCR fallback, chunking, embedding, index write, status updates |
| `ask` | History, query rewriting, hybrid retrieval, generation, persistence |
| `workspace` | Chat CRUD, feedback, statistics |
| `study_api` / `study_worker` | Async study-material generation |
| `rag_core` / `study_core` | Pure algorithms (unit-tested) |
### 4.3 Data model
**DocumentsTable** — PK `userId`, SK `docId`: `filename, ext, key, status, pages, chunks, ocr, error, createdAt`.
**ActivityTable (single-table)** — PK `userId`, SK:
| SK pattern | Meaning |
|---|---|
| `SESSION#<sid>` | chat title, updatedAt |
| `MSG#<sid>#<ns-timestamp>` | message (role, text, sources, confidence) |
| `FB#<ns-timestamp>` | feedback |
| `JOB#<jobId>` | study job (status, result, TTL 7 days) |
**S3** — `uploads/<user>/<doc>/source.<ext>`; `vectors/<user>/<doc>.json` = `{chunks:[{id,page,text,embedding[512]}]}`.
### 4.4 Processing pipeline
`Upload → S3 event → extract (pypdf | Textract) → chunk(1000/200, page-aware) → embed (Titan V2, 512-d, 6 threads) → write index → READY`.
### 4.5 Retrieval algorithm
Given query *q* and chunk set *C*:
1. Vector score `s_v(c) = cos(E(q), E(c))`.
2. Keyword score `s_b(c) = BM25(q, c)`.
3. Rankings `R_v` (top 20, `s_v ≥ 0.15`) and `R_b` (top 20, `s_b > 0`).
4. Fusion `RRF(c) = Σ 1/(60 + rank_r(c))`.
5. MMR selection of K=5: `argmax λ·rel(c) − (1−λ)·max_{s∈S} cos(c,s)` with λ = 0.7.
6. If the fused set is empty → return "not found" without calling the LLM.
### 4.6 Generation
System prompt enforces: answer only from numbered passages, cite `[n]`, refuse when absent, ignore instructions inside passages. Temperature 0.2. Optional style suffixes. Chat history is passed as prior turns; the new user turn contains retrieved context.
### 4.7 Confidence heuristic
Best cosine score ≥ 0.55 → *high*, ≥ 0.35 → *medium*, otherwise *low* (calibrated for Titan V2; shown to the user as guidance, not a guarantee).
### 4.8 Study Studio
`POST /study` → job `PENDING` → async Lambda → `RUNNING` → `DONE/FAILED`. Summary: batches of ≈12 k chars (max 8, sampled evenly) → parallel partial summaries → reduce into Overview / Key Points / Terms / Conclusion. Flashcards, quiz, key terms: evenly sample chunks, request JSON, extract & validate.

## 5. Implementation
### 5.1 Technology stack
Python 3.12 (Lambda), pypdf, boto3, AWS SAM, vanilla JavaScript/HTML/CSS (no build step), Mermaid diagrams, pytest, GitHub Actions.
### 5.2 Key engineering points
- **Presigned POST** with `content-length-range` → server-enforced limits without a Lambda in the upload path.
- **Warm cache** of vector files in the Lambda execution environment.
- **Retries:** adaptive retry mode for Bedrock throttling.
- **30-second API limit** circumvented by asynchronous worker + polling.
- **Escape-first Markdown renderer** → no XSS from document or model content.
- **Token refresh** in the SPA using Cognito refresh tokens.
### 5.3 Infrastructure as code
`template.yaml` provisions buckets, tables, Cognito, API, six functions with least-privilege policies, CloudFront (OAC), SNS topic, two alarms and a dashboard. `deploy.sh` runs tests, deploys and publishes the UI.

## 6. Security Analysis (STRIDE summary)
| Threat | Mitigation |
|---|---|
| Spoofing | Cognito authentication; JWT verified at API Gateway |
| Tampering | Presigned POST conditions; IAM least privilege; IDs regex-validated |
| Repudiation | CloudWatch logs, X-Ray traces |
| Information disclosure | userId in every key; private encrypted buckets; short-lived URLs |
| Denial of service | API throttling; file/size/chunk limits; Lambda concurrency limits |
| Elevation of privilege | Separate minimal IAM policy per Lambda |
| Prompt injection | Document text declared untrusted in system prompt; output only displayed as text |
| XSS | Escape-first rendering, `textContent` for untrusted strings, CloudFront security headers |

## 8. Cost Analysis
Assuming 50 documents × 100 pages and 500 questions per month: embeddings ≈ 150k tokens (cents); answers ≈ 500 × ~2.5k input tokens with a Haiku-class model (cents to low dollars); DynamoDB, Lambda, API Gateway, S3, CloudFront within or near free tier; Textract only for scanned PDFs (≈ $1.50 / 1,000 pages). **Order of magnitude: a few dollars per month; ≈ $0 when idle.** (Verify with the AWS Pricing Calculator.)

The project demonstrates an end-to-end, production-style RAG system on AWS that is accurate (grounded + cited), secure (per-user isolation), economical (serverless) and useful beyond Q&A (study tools).
